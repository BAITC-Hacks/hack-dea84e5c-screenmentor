# Размещение Графа денег в NVIDIA Brev

Инструкция подготовлена 23 сентября 2026 года. Она запускает текущую версию проекта на синтетическом наборе. Создание сервера расходует кредит Brev; точные тариф, доступность CPU и условия промокода проверяются в вашей консоли. Сама инструкция не создаёт облачных ресурсов.

Перед подготовкой инструкции Docker-образ собран из функционального кода версии 6212c3b и запущен локально как Linux-контейнер. Проверены непривилегированный пользователь, volume результатов, отказ без пароля, успешный вход, учебные данные, интерфейс, инструкция, логотип и XLSX. Проверочный контейнер остановлен. Сервер Brev и его внешняя ссылка этой проверкой не создавались.

## 1. Как использовать кредит

Для текущего проекта полезнее всего обеспечить независимую от ноутбука работающую ссылку для жюри. Вычисления выполняются на CPU; установка приложения на GPU-сервер сама по себе не ускоряет NetworkX и не добавляет AI-функций.

В консоли выберите минимальную подходящую конфигурацию. Ориентир для выданного небольшого набора: 2 vCPU, 4 ГБ RAM и 20 ГБ диска; это стартовая рекомендация, не результат нагрузочного теста. Если доступны CPU instances, начните с них. Если кредит применим только к GPU-вариантам, выберите самый дешёвый подходящий вариант по итоговой цене, без необходимости в A100/H100. Режим — VM Mode; нужен Docker.

Бюджет времени приблизительно равен остатку кредита, делённому на общую часовую стоимость. Например, $50 / $0,50 = 100 часов без дополнительных расходов. Это арифметический пример, не тариф Brev. Остановка приложения внутри VM не останавливает оплату VM. При остановке instance вычислительные начисления прекращаются, но хранилище может оплачиваться. Пока instance остановлен, сайт недоступен.

Проверьте срок действия кредита и настройки Auto recharge. Не допускайте нулевого баланса во время проверки: Brev может остановить или удалить ресурсы. В течение согласованного периода оценки сервер должен оставаться работающим. [Жизненный цикл и оплата](https://docs.nvidia.com/brev/concepts/gpu-instances), [Billing в консоли](https://docs.nvidia.com/brev/guides/console-reference).

## 2. Создать сервер и открыть терминал

1. Откройте [Brev Console](https://brev.nvidia.com/), выберите организацию с кредитом.
2. Нажмите Create Instance или Create Environment, в зависимости от интерфейса аккаунта.
3. Выберите оборудование, VM Mode и имя `screenmentor`; проверьте итоговую цену до Deploy.
4. Дождитесь Running. Через Access откройте предоставленный терминал или подключитесь по указанной там SSH-команде. Если включён JupyterLab, можно открыть его Terminal.

Следующие команды предназначены для **Bash на сервере Brev**, не для PowerShell ноутбука. В режиме VM Docker предоставляется платформой. [Конфигурации Brev](https://docs.nvidia.com/brev/concepts/launchables).

## 3. Скачать актуальную версию

```bash
mkdir -p ~/workspace
cd ~/workspace
git clone --branch codex/graph-money --single-branch https://github.com/BAITC-Hacks/hack-dea84e5c-screenmentor.git
cd hack-dea84e5c-screenmentor
git log -1 --oneline
docker build -t screenmentor:demo .
```

Используется ветка `codex/graph-money`: именно в неё отправлены последние улучшения. Не заменяйте её на main, пока актуальные изменения не объединены. Если репозиторий уже скачан, вместо повторного clone перейдите в его каталог, проверьте ветку и выполните `git pull --ff-only`.

Если GitHub требует вход, используйте штатную авторизацию GitHub или SSH-ключ сервера; не вставляйте токен в URL репозитория и не сохраняйте его в исходниках. При ошибке доступа к Docker попробуйте те же docker-команды через `sudo`; для запуска с переменной пароля понадобится `sudo --preserve-env=GRAPH_ACCESS_PASSWORD docker run ...`.

## 4. Запустить приложение

Введите отдельный непустой пароль для демо. Он не будет показан при вводе. Это пароль приложения, не пароль NVIDIA.

```bash
read -r -s -p 'Demo password: ' GRAPH_ACCESS_PASSWORD
printf '\n'
export GRAPH_ACCESS_PASSWORD
test -n "$GRAPH_ACCESS_PASSWORD" && docker run -d \
  --name screenmentor \
  --restart unless-stopped \
  -p 8765:8765 \
  -e GRAPH_ACCESS_PASSWORD \
  -v screenmentor-results:/app/artifacts \
  screenmentor:demo
unset GRAPH_ACCESS_PASSWORD
```

Логин приложения — `analyst`. Без GRAPH_DATA_DIR сервер использует синтетический пример. Docker volume хранит файлы результатов отдельно от контейнера; список активных запусков всё равно находится в памяти и не переживает перезапуск. Пароль сохраняется в конфигурации контейнера и доступен администратору Docker; не используйте пароль от личного аккаунта.

Не открывайте TCP 8765 для всех IP в настройках Brev: доступ предоставьте через HTTPS Secure Link. Это также не позволит обходить HTTPS и отправлять пароль непосредственно по открытому HTTP.

Проверка на самом сервере:

```bash
docker logs --tail 40 screenmentor
curl --fail --user analyst http://127.0.0.1:8765/api/health
```

curl запросит пароль отдельно. Успешный ответ содержит `"status":"ok"`. В логах должно быть `Application startup complete`. Если приложение ещё начинает работу, повторите проверку после этого сообщения.

## 5. Получить ссылку для проверки

В настройках instance откройте Access либо Network → Secure Links, укажите имя `screenmentor` и порт **8765**, создайте ссылку. Откройте выданный HTTPS URL. Если сервис возвращает 502, сначала проверьте curl из предыдущего шага и правильность порта.

**Secure Link защищён авторизацией NVIDIA/Brev.** Чтобы жюри смогло открыть сервис, настройте доступ через Share a Service / Edit Access и проверьте его из другого аккаунта. Ссылка на Launchable — это рецепт создания новой VM, а не адрес уже работающего сайта. Для сдачи нужна ссылка на запущенный сервис и необходимые данные доступа. [Secure Links и доступ](https://docs.nvidia.com/datascience/deployment/stable/cloud/nvidia/brev/), [Console Access](https://docs.nvidia.com/brev/guides/console-reference).

Дополнительно приложение запросит логин `analyst` и введённый пароль. Передайте их жюри предусмотренным организатором способом; не помещайте пароль в README или Git. Наличие двух уровней входа нужно проверить заранее, особенно если проверка автоматизирована.

Если проверяющим нужна обычная ссылка **без аккаунта NVIDIA**, используйте HTTPS reverse proxy с доменом либо управляемый Cloudflare Tunnel к этому же серверу. В качестве временного теста, после [установки cloudflared](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/), на сервере можно выполнить:

```bash
cloudflared tunnel --url http://127.0.0.1:8765
```

Это создаёт публичный случайный HTTPS URL; пароль приложения остаётся включённым. Процесс туннеля должен продолжать работать. Quick Tunnel предназначен для тестирования, не гарантирует доступность и не является постоянным адресом для длительной оценки; для окончательной ссылки используйте управляемый туннель. [Ограничения Quick Tunnels](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/).

## 6. Проверить сайт с телефона

Откройте HTTPS-ссылку через мобильный интернет, пройдите предусмотренную авторизацию, найдите счёт, откройте цепочку и скачайте XLSX. Ноутбук после переноса приложения на Brev не участвует в обслуживании сайта; Brev instance и используемый туннель должны оставаться включёнными.

Сначала проверяйте размещение на синтетическом примере. Файлы организатора не добавляйте в Git и не загружайте в общедоступное демо. Загрузка данных в приложение на Brev передаёт их в облако; используйте для кейса только разрешённый организатором закрытый доступ. Один сервер приложения — общее рабочее место без изоляции пользователей.

## 7. Обновления и эксплуатация

Из каталога репозитория получите изменения через `git pull --ff-only` и соберите новый образ. Пересоздание контейнера прервёт текущие запросы и сбросит запуски в памяти; выполняйте его между проверками и предварительно скачайте необходимые результаты. Не удаляйте volume с нужными файлами.

Чтобы временно остановить только приложение, используйте `docker stop screenmentor`, затем `docker start screenmentor`. Чтобы остановить начисления за вычисления, остановите **instance в Brev** после завершения необходимого периода доступа. Удаление instance необратимо удаляет его данные; заранее сохраните нужные материалы. Основной код уже хранится в командном GitHub.

После фактического размещения запишите рабочий URL, развёрнутый коммит, дату проверки с внешней сети и режим доступа в материалы сдачи. Пока эти действия не выполнены, инструкция не означает, что облачный сайт уже запущен.
