# Размещение Графа денег в NVIDIA Brev

## Текущее размещение

Проект размещён по адресу **https://screenmentor-uwfohh6hz.gobrev.dev**. Для сервиса screenmentor включён публичный доступ: Share → Disable authentication. Приложение также работает без логина и пароля. Jupyter используется только для обслуживания сервера и остаётся закрытым.

В инструкции описаны запуск и обновление приложения. Secure Link принимает HTTPS-запросы на порту 443 и направляет их на порт приложения 8765. Текущую версию на сервере можно узнать командой `git rev-parse HEAD` в каталоге проекта.

Локально проверены Linux-контейнер и основные сценарии: запуск от непривилегированного пользователя, сохранение результатов в volume, API, интерфейс, инструкцию, логотип и скачивание XLSX. В актуальной версии проверка пароля удалена; тесты покрывают открытый доступ к странице, API и инструкции.

## 1. Как использовать кредит

Для текущего проекта полезнее всего обеспечить независимую от ноутбука работающую ссылку для жюри. Вычисления выполняются на CPU; установка приложения на GPU-сервер сама по себе не ускоряет NetworkX и не добавляет AI-функций.

В консоли выберите минимальную подходящую конфигурацию. Ориентир для выданного небольшого набора: 2 vCPU, 4 ГБ RAM и 20 ГБ диска; это стартовая рекомендация, не результат нагрузочного теста. Если доступны CPU instances, начните с них. Если кредит применим только к GPU-вариантам, выберите самый дешёвый подходящий вариант по итоговой цене, без необходимости в A100/H100. Режим — VM Mode; нужен Docker.

Бюджет времени приблизительно равен остатку кредита, делённому на общую часовую стоимость. Например, $50 / $0,50 = 100 часов без дополнительных расходов. Это арифметический пример, не тариф Brev. Остановка приложения внутри VM не останавливает оплату VM. При остановке instance вычислительные начисления прекращаются, но хранилище может оплачиваться. Пока instance остановлен, сайт недоступен.

Проверьте срок действия кредита и настройки Auto recharge. Не допускайте нулевого баланса во время проверки: Brev может остановить или удалить ресурсы. В течение согласованного периода оценки сервер должен оставаться работающим. [Жизненный цикл и оплата](https://docs.nvidia.com/brev/concepts/gpu-instances), [Billing в консоли](https://docs.nvidia.com/brev/guides/console-reference).

## 2. Создать сервер и открыть терминал

1. Откройте [Brev Console](https://brev.nvidia.com/), выберите организацию с кредитом.
2. Нажмите Create Instance или Create Environment, в зависимости от интерфейса аккаунта.
3. Выберите оборудование, VM Mode и имя `screenmentor`; проверьте итоговую цену до Deploy.
4. Дождитесь Running. Через Access откройте предоставленный терминал или подключитесь по указанной там SSH-команде. Если включён JupyterLab, можно открыть его Terminal.

Следующие команды предназначены для **Bash на сервере Brev**, не для PowerShell ноутбука. В режиме VM Docker предоставляется платформой. [Конфигурации Brev](https://docs.nvidia.com/brev/concepts/launchables).

## 3. Скачать актуальную версию

```bash
mkdir -p ~/workspace
cd ~/workspace
git clone --branch main --single-branch https://github.com/BAITC-Hacks/hack-dea84e5c-screenmentor.git
cd hack-dea84e5c-screenmentor
git log -1 --oneline
docker build -t screenmentor:demo .
```

Актуальная версия находится в `main`. Если репозиторий уже скачан, получите изменения и переключитесь на основную ветку по командам раздела 7.

Если GitHub требует вход, используйте штатную авторизацию GitHub или SSH-ключ сервера; не вставляйте токен в URL репозитория и не сохраняйте его в исходниках. При ошибке доступа к Docker попробуйте те же docker-команды через `sudo`.

## 4. Запустить приложение

Приложение запускается без логина и пароля. Старая переменная GRAPH_ACCESS_PASSWORD игнорируется. Публичное демо использует синтетический набор.

```bash
docker run -d \
  --name screenmentor \
  --restart unless-stopped \
  -p 8765:8765 \
  -v screenmentor-results:/app/artifacts \
  screenmentor:demo
```

Docker volume сохраняет файлы результатов. Загруженные запуски в памяти сбрасываются при перезапуске. Для внешнего доступа используйте HTTPS-ссылку.

Проверка на самом сервере:

```bash
docker logs --tail 40 screenmentor
curl --fail http://127.0.0.1:8765/api/health
```

Успешный ответ содержит `"status":"ok"`. В логах должно быть `Application startup complete`. Если приложение ещё начинает работу, повторите проверку после этого сообщения.

## 5. Получить ссылку для проверки

В настройках instance откройте Access либо Network → Secure Links, укажите имя `screenmentor` и порт **8765**, создайте ссылку. Откройте выданный HTTPS URL. Если сервис возвращает 502, сначала проверьте curl из предыдущего шага и правильность порта.

**Настройка Brev выполняется отдельно от приложения.** Откройте Share у сервиса screenmentor, включите Disable authentication и нажмите Done. В строке сервиса должно появиться Authorization: Public; не путайте IP Restrictions: Anywhere с отключением авторизации. Jupyter оставьте закрытым. Проверьте ссылку в инкогнито без NVIDIA-сессии.

[Secure Links и доступ](https://docs.nvidia.com/datascience/deployment/stable/cloud/nvidia/brev/), [Console Access](https://docs.nvidia.com/brev/guides/console-reference).

Для альтернативного размещения без Secure Link можно использовать HTTPS reverse proxy с доменом либо управляемый Cloudflare Tunnel к этому же серверу. В качестве временного теста, после [установки cloudflared](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/), на сервере можно выполнить:

```bash
cloudflared tunnel --url http://127.0.0.1:8765
```

Это создаёт публичный случайный HTTPS URL; приложение доступно без авторизации. Процесс туннеля должен продолжать работать. Quick Tunnel предназначен для тестирования, не гарантирует доступность и не является постоянным адресом для длительной оценки; для окончательной ссылки используйте управляемый туннель. [Ограничения Quick Tunnels](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/).

## 6. Проверить сайт с телефона

Откройте HTTPS-ссылку через мобильный интернет, убедитесь, что вход не требуется, найдите счёт, откройте цепочку и скачайте XLSX. Ноутбук после переноса приложения на Brev не участвует в обслуживании сайта; Brev instance и используемый туннель должны оставаться включёнными.

Сначала проверяйте размещение на синтетическом примере. Файлы организатора не добавляйте в Git и не загружайте в общедоступное демо. Загрузка данных в приложение на Brev передаёт их в облако; используйте для кейса только разрешённый организатором закрытый доступ. Один сервер приложения — общее рабочее место без изоляции пользователей.

## 7. Обновления и эксплуатация

После изменений в GitHub сайт сам не обновляется. В терминале Brev из каталога репозитория выполните:

```bash
cd ~/workspace/hack-dea84e5c-screenmentor
git fetch origin main:refs/remotes/origin/main
git switch main
git pull --ff-only origin main
git log -1 --oneline
docker build -t screenmentor:demo .
```

При клонировании через созданный SSH-ключ перед git pull задайте `export GIT_SSH_COMMAND="ssh -i $HOME/.ssh/screenmentor_github -o IdentitiesOnly=yes"`. При необходимости запустите `eval "$(ssh-agent -s)"` и `ssh-add ~/.ssh/screenmentor_github`.

Только после успешной сборки и сохранения нужных выгрузок остановите и удалите старый контейнер. Именованный volume результатов при этом сохраняется:

```bash
docker stop screenmentor
docker rm screenmentor
```

Повторите блок запуска из раздела 4 без переменных пароля. Проверьте health, откройте прежнюю HTTPS-ссылку и обновите страницу с очисткой кеша — Ctrl+Shift+R. Secure Link пересоздавать не нужно: порт остаётся 8765.

Из каталога репозитория получите изменения через `git pull --ff-only` и соберите новый образ. Пересоздание контейнера прервёт текущие запросы и сбросит запуски в памяти; выполняйте его между проверками и предварительно скачайте необходимые результаты. Не удаляйте volume с нужными файлами.

Чтобы временно остановить только приложение, используйте `docker stop screenmentor`, затем `docker start screenmentor`. Чтобы остановить начисления за вычисления, остановите **instance в Brev** после завершения необходимого периода доступа. Удаление instance необратимо удаляет его данные; заранее сохраните нужные материалы. Основной код уже хранится в командном GitHub.

Перед сдачей необходимо проверить ссылку из внешней сети без авторизации и сверить коммит на сервере с основной веткой репозитория. Перезапуск сбрасывает загруженные запуски в памяти; заметки браузера остаются привязаны к адресу сайта и набору.
