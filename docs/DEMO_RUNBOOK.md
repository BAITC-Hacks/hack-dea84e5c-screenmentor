# Demo Day runbook — ИИ Наставник / ЖИ Көмекші

**Версия продукта:** 0.24.11

**Продолжительность основного показа:** 5–6 минут
**Цель:** доказать не «возможность вызвать LLM», а практическую помощь человеку, который сам выполняет действие и понимает его смысл.

Этот документ — сценарий живой демонстрации. Он рассчитан на ноутбук с загруженным unpacked-расширением, запущенным backend и только синтетическими данными. Не заменяйте неработающую функцию скриншотом или не выдавайте mock за реальную проверку.

## 1. Что должен понять зритель

К концу показа жюри должно увидеть пять вещей:

1. Помощник находится прямо рядом с интерфейсом и объясняет **видимые** элементы, а не показывает универсальную статью.
2. Пользователь сохраняет контроль: агент подсказывает и подсвечивает, но не кликает и не отправляет данные.
3. Русский и казахский — реальные режимы интерфейса и вопроса, а не два текста на одном экране.
4. Голос снижает барьер для человека, которому трудно печатать; текст после остановки записи идёт в ИИ автоматически.
5. Безопасность и конфиденциальность встроены в продукт: опасный URL показывает предупреждение, а документ, пароль и содержимое полей не читаются.

Не тратьте время на список библиотек, размер модели, все 157 тестов или обещания «работает на любом сайте». Технологии показывайте только после пользовательской ценности.

## 2. Выбор сценария

### Основной сценарий: синтетический учебный магазин

Используйте `http://127.0.0.1:8787/demo`. На нём только вымышленные данные и стабильные подписанные элементы:

- поле «Поиск товара / Тауар іздеу»;
- кнопка «Найти / Іздеу»;
- после поиска — список выбора «Город / Қала»;
- кнопка «Открыть / Ашу»;
- кнопка возврата к результатам;
- учебный рекламный баннер.

Преимущество: сценарий не зависит от реального магазина, учётной записи, цены товара, персональных данных и изменения чужого дизайна.

### Дополнительный сценарий: Word или Excel Online

Показывайте только на пустом учебном файле без личных данных и только после того, как в этот день успешно прошли TC-28 или TC-29 из [ручной приёмки](MANUAL_ACCEPTANCE_CATALOG.md). Демонстрируйте фиксированную команду ленты, например «Формулы»/«Автосумма» в Excel или «Главная»/«Вставка» в Word.

Не демонстрируйте содержимое ячеек, формулы из реальной работы, имя файла, аккаунт или комментарии. Агент специально не читает эти данные.

### Что не выбирать для основного показа

- непроверенный реальный интернет-магазин с hover-каталогом;
- страницу с персональными данными, перепиской, банковским кабинетом или настоящим платёжным действием;
- настоящий фишинговый сайт;
- функцию, которая не прошла preflight именно на этом компьютере и в этой сети.

## 3. Подготовка до Demo Day

### 3.1. Один раз заранее

1. Установить Node.js 22, Chrome/Edge и зависимости: `npm ci`.
2. Создать `.env.local`: `npm run setup`.
3. Настроить выбранный provider (`glm`, `qwen` или `ollama`) и записать, какой именно provider используется в демо.
4. При показе голоса добавить `AZURE_SPEECH_KEY` и `AZURE_SPEECH_REGION`; без них голосовой сценарий не обещать.
5. При live-показе Site Risk добавить `SAFE_BROWSING_API_KEY`; не показывать ключ на экране.
6. Выполнить `npm test` и `npm run check`; записать commit, версию 0.24.11, браузер и Windows в карточку тестирования.
7. В `chrome://extensions` загрузить папку `extension` как unpacked extension. После любого обновления кода нажимать кнопку обновления расширения и обновлять тестовую вкладку.
8. Открыть popup расширения, сохранить pairing-токен, полученный по закрытому каналу, и корректный backend URL. Ключ модели в popup не вводится; bearer-токен не показывается на экране и не попадает в материалы демо.

### 3.2. За 20–30 минут до выступления

1. Запустить backend:

   ```powershell
   npm start
   ```

2. Открыть `http://127.0.0.1:8787/health`. Убедиться, что ответ содержит `status: "ok"`; для вопроса — capability `questions-v1`; для голоса — `speech-v1` и `speech-to-text-v1`.
3. В popup нажать «Проверить подключение». Убедиться, что pairing token сохранён, model configured и backend доступен. Для Render используйте только HTTPS URL; после Demo Day токен отозвать.
4. Открыть отдельную вкладку `http://127.0.0.1:8787/demo`, масштаб браузера — 100 %; закрыть все лишние вкладки и уведомления.
5. Открыть панель наставника, убедиться, что кнопки, инструкция, question form, подсветка и `Esc` работают.
6. Сделать один короткий реальный RU/KK запрос модели. Не использовать его как заученный ответ, а проверить сеть, квоту и язык.
7. Если в демо будет голос, один раз выдать permission на этом профиле, записать короткую фразу и включить/выключить озвучивание.
8. Подготовить запасной чистый профиль браузера, если хотите показать «казахский по умолчанию». В уже использованном профиле сохранённый выбор языка намеренно не сбрасывается.

### 3.3. За 2–3 минуты до выступления

- Если backend на Render Free: открыть `<render-url>/health`, чтобы разбудить сервис; затем снова проверить connection в popup. У cold start может занять около минуты.
- Переключить Windows в режим «Не беспокоить», отключить всплывающие мессенджеры и скрыть список загрузок/закладок.
- Проверить заряд/питание, микрофон, громкость, интернет и зеркалирование экрана.
- Открыть на старте именно учебный магазин; ничего не печатать в полях заранее.
- Подготовить карточку с запасным планом на случай отсутствия сети/микрофона.

## 4. Preflight: обязательные отметки

Не начинайте показ, пока все обязательные пункты не имеют статус «пройден».

| Проверка | Действие | Статус |
| --- | --- | --- |
| Расширение | Иконка наставника видна на `/demo`, панель открывается/закрывается | ☐ |
| Язык | На чистом профиле panel и popup начинают с KK; выбранный RU/KK остаётся после reopening | ☐ |
| Local help | «Инструкция пользования» раскрывается внутри панели при отключённом backend | ☐ |
| Learn | «Изучить страницу» показывает объяснение и корректную рамку либо честный fallback | ☐ |
| Picker | «Что это?» по «Найти» не запускает поиск; `Esc` завершает выбор | ☐ |
| Question | Вопрос выдаёт один следующий шаг; «Далее» после ручного поиска использует свежий экран | ☐ |
| Voice | Пользовательский prompt микрофона, stop → transcript → вопрос; проверены RU и KK | ☐ / не показывать |
| TTS | Речь начинается, кнопка выключения немедленно останавливает звук | ☐ / не показывать |
| Site Risk | Clean URL не вызывает notice; controlled risk response показывает маленькое notice | ☐ / не показывать |
| Deployment | `/health` и popup connection готовы на выбранном backend | ☐ |

Если опциональная строка не пройдена, не пытайтесь «починить на сцене». Используйте план Б и прямо назовите не показанную функцию опциональной.

## 5. Основной сценарий: 5–6 минут

### 0:00–0:35 — проблема и обещание

**На экране:** учебный магазин, без открытой панели.

**Скажите:**

> «Когда человек не уверен в цифровых сервисах, инструкция часто говорит только “нажмите сюда”. Но непонятно, зачем нужна кнопка и что произойдёт дальше. Наш ИИ Наставник объясняет интерфейс прямо в момент работы — на русском и казахском — и не делает действие за человека».

Нажмите иконку внизу справа. Покажите компактность панели, название «ЖИ Көмекші» и расположение кнопки закрытия отдельно от основных действий.

**Нужно доказать:** продукт встроен в текущую страницу и не перекрывает её целиком.

### 0:35–1:35 — объяснение интерфейса, а не автоклик

**На экране:** панель открыта, учебный магазин в исходном состоянии.

1. Нажмите **«Инструкция пользования»** / «Пайдалану нұсқаулығы» на 2–3 секунды. Покажите, что панель не закрылась; сверните инструкцию.
2. Нажмите **«Изучить страницу»** / «Бетті үйрену».
3. Покажите первую bubble-подсказку и рамку; нажмите «Далее» до объяснения поля поиска или кнопки «Найти».
4. Скажите:

> «Помощник видит только безопасное описание видимых элементов: например, тип кнопки, подпись и состояние. Он не читает введённый текст, карточки товаров или весь HTML».

5. Нажмите **«Что это?»**, укажите на кнопку «Найти / Іздеу», затем нажмите её в режиме выбора.

**Скажите:**

> «Сейчас мы выбрали кнопку для объяснения. Сам магазин не начал поиск: пользователь сам решает, выполнять действие или нет».

Если рамка не найдена, не нажимайте случайную кнопку. Скажите: «Интерфейс изменился или цель не найдена; наставник не подменяет её похожим элементом» и перейдите к плану Б.

### 1:35–2:45 — своя цель и контекст после действия

**На экране:** вернитесь к исходному состоянию `/demo`; откройте «Задать вопрос».

1. Покажите, что block раскрывается вертикально и содержит placeholder и зелёную кнопку «Получить ответ».
2. Введите (без реальных данных):

   ```text
   Как найти учебный шуруповерт и выбрать город?
   ```

3. Нажмите «Получить ответ». Пока идёт запрос, скажите:

> «В модель передаётся мой явный вопрос и очищенное описание текущих кнопок. Она должна дать только один следующий безопасный шаг, а не пообещать, что товар найден».

4. Когда появится шаг, вручную введите в поле `Шуруповерт` и нажмите **«Найти»** на сайте.
5. Покажите, что появились «Город / Қала» и «Открыть / Ашу». Нажмите «Далее» в bubble.

**Скажите:**

> «После ручного действия помощник собирает новый безопасный контекст. Он не считает свой прошлый совет доказательством, что пользователь уже выполнил задачу».

Если модель отвечает долго, не ждите более 15 секунд молча: покажите ранее работающий режим «Что это?» или local instruction, скажите «облачный ответ сейчас недоступен; интерфейсный режим и проверенная справка остаются доступны», затем перейдите к завершающей части.

### 2:45–3:50 — казахский и голос

**На экране:** selector языка внизу панели.

1. Если текущий язык RU, переключите на **Қазақша**; если KK, подчеркните, что это стартовый язык чистого профиля.
2. Скажите:

> «Тіл таңдау бір рет сақталады: ол панельде де, кеңейтімнің баптауларында да қолданылады».

3. Нажмите **«Дауысты жазу»**. Если permission page открывается, покажите собственную понятную кнопку разрешения и browser prompt; не показывайте системные настройки.
4. Произнесите короткую безопасную фразу, например:

   ```text
   Қала сүзгісін қалай таңдаймын?
   ```

5. Нажмите **«Жазуды тоқтату»**. Покажите, что текст не остаётся простым черновиком, а автоматически запускает запрос к ИИ.
6. Включите **«Дыбыстау»** на короткий фрагмент ответа, затем выключите через 1–2 секунды.

**Скажите:**

> «Запись не сохраняется в файл или базу. После остановки она превращается в текст и проходит те же ограничения безопасности, что обычный вопрос. Озвучивание можно остановить сразу, а текст остаётся видимым».

Если Azure Speech не прошёл preflight, не изображайте голос. Скажите: «Голосовой поток подключается через Azure Speech, но для этого показа он отключён; основной текстовый сценарий работает», и продолжите с 3:50.

### 3:50–4:45 — безопасность без запугивания

**На экране:** обычная чистая HTTPS-страница или `/demo`.

1. Сначала скажите: «На чистом адресе уведомления нет — мы не отвлекаем пользователя фразой “сайт безопасен”».
2. Покажите live предупреждение **только если** preflight проверил controlled backend result `SOCIAL_ENGINEERING` или `MALWARE`.
3. Покажите маленькое окно у иконки, прочитайте главный смысл: не вводить пароль, коды и платёжные данные.

**Скажите:**

> «Это не блокировка и не антивирус. Расширение предупреждает, а решение остаётся за человеком. В Google уходит не полный адрес, а только короткие hash-prefixes; сам адрес не логируется приложением».

Никогда не демонстрируйте настоящий вредоносный URL. Если controlled result не подготовлен, пропустите live-card и скажите: «Предупдение тестируется контролируемым ответом backend; на чистом сайте интерфейс молчит».

### 4:45–5:30 — доверие, масштабирование и финал

Откройте popup расширения на 10–15 секунд. Не показывайте token: достаточно показать, что есть URL HTTPS/local backend, статус подключения и кнопка «Забыть».

**Скажите:**

> «Ключ модели остаётся на сервере, а код подключения нельзя прочитать обратно из расширения. Мы не читаем текст документа Word, ячейки Excel, переписку или значения полей. Уже есть безопасный каталог проверенных команд Word и Excel; дальше расширяем его только после проверки».

Финальная фраза:

> «ИИ Наставник не заменяет пользователя. Он помогает понять следующий шаг, безопасно выполнить его самому и постепенно стать самостоятельнее».

## 6. Сокращённый сценарий на 3 минуты

Если организатор ограничил время:

1. **0:00–0:30:** проблема + открытие панели на `/demo`.
2. **0:30–1:20:** «Изучить страницу» + «Что это?» по кнопке поиска, показать отсутствие автоклика.
3. **1:20–2:15:** переключение на KK + короткий voice question, если он прошёл preflight; иначе typed question.
4. **2:15–2:45:** controlled Safe Browsing warning либо объяснение, почему на clean URL нет карточки.
5. **2:45–3:00:** privacy limit и финальная ценность.

Не пытайтесь вместить Office, adblock и все настройки в три минуты.

## 7. План Б при сбоях

| Сбой | Что сделать на сцене | Чего не делать |
| --- | --- | --- |
| Backend/model не отвечает | Показать «Инструкция пользования», `Что это?`/fallback по наблюдаемой кнопке, рассказать о честном сообщении ошибки. | Не ждать долго молча и не говорить, что модель ответила. |
| Render cold start | Открыть заранее разогретый `/health`; если не помогло, перейти на локальный backend или offline UI. | Не переключать URL/токен перед жюри без проверки. |
| Нет сети | Открыть уже загруженный `/demo`, показать local instruction/picker и явно сказать, что online AI/safety check не запускаются без сети. | Не выдавать prepared UI за live model. |
| Microphone denied/не работает | Использовать заранее подготовленный typed KK question. | Не открывать настройки Windows и не просить жюри ждать. |
| Нет TTS | Оставить ответ текстом, выключить кнопку, назвать отсутствие подходящего голоса/облака. | Не включать русский голос для казахского текста. |
| Подсветка Office не найдена | Продолжить текстом fixed curriculum и сказать, что агент не выбрал похожую кнопку. | Не рисовать рамку вручную или не кликать случайный элемент. |
| Site Risk test не готов | Показать отсутствие лишнего notice на clean URL и объяснить тестирование controlled response. | Не открывать реальный phishing/malware URL. |
| Страница изменилась | Нажать «Завершить», перезагрузить synthetic demo или начать новый safe snapshot. | Не использовать старую bubble как будто она относится к новому экрану. |

## 8. Роли команды

Если выступают двое:

| Роль | Ответственность |
| --- | --- |
| Спикер | Ведёт историю пользователя, произносит ключевые тезисы и не переключается на терминал. |
| Оператор | Делает клики по runbook, следит за таймингом, backend health, сетью и планом Б. |

Если выступает один человек, заранее положите рядом распечатанную карточку с пятью шагами: `open panel → learn/picker → question → KK voice → safety/privacy`.

## 9. После показа: вопросы жюри

| Вопрос | Короткий честный ответ |
| --- | --- |
| «Может ли он сам оформить заказ?» | Нет. Он объясняет последствия и предлагает следующий шаг; действие остаётся у пользователя. |
| «Вы читаете страницу целиком?» | Нет. Передаём только ограниченные descriptors видимых элементов; текст полей, чатов, документов и ячеек запрещён. |
| «Работает на любом сайте?» | Нет гарантии. Основной режим работает с безопасно распознанными видимыми controls; динамические меню и нестандартные UI требуют отдельной проверки. |
| «Почему нужен backend?» | Он держит API-ключи вне расширения, проверяет схемы/лимиты и подключает модель, Speech и Safe Browsing. |
| «Что происходит с голосом?» | Запись обрабатывается в памяти для распознавания, не сохраняется локально; Azure получает audio согласно своим условиям. |
| «Что даёт Safe Browsing?» | Предупреждает о найденной угрозе или подозрительном адресе, но не заменяет антивирус и не гарантирует безопасность. |
| «Как это масштабировать?» | Добавлять проверенные каталоги интерфейсов и user-tested scenarios; для чтения Office documents нужен отдельный Add-in и согласие. |
